## 二、复查明细

### 1. 数据层（quiz_repository_mock.dart / quiz_repository.dart）

**随机组卷 `generateCompositePaper()`**
- 第一轮按学科配额抽题：`SELECT ... WHERE bank_id=? AND type=? AND status='active' ORDER BY RANDOM() LIMIT ?` —— SQL 正确，卷内 `seen` 去重
- 第二轮缺口补足：某题型不足期望时从全库同题型随机补齐，保证**每卷题型数量稳定**（多选放宽方案的核心）
- 学科配额多选改动后总分仍精确 **150**（现汉 57 + 古汉 57 + 现代 17 + 当代 16 + 古代 3）

**交卷 `submitMockSession()`（150 分制）**
- `pointsByType` 为空走原百分制（单科卷不受影响）；非空走加权计分
- 正确满分、**部分正确半分**（`(pts/2).round()`）
- 成绩写入与返回同一 `score` 变量，与落库一致
- 单事务原子写入（成绩单 → 逐题日志 → 回填汇总）✓

**数据兼容**
- 不新增表/列，`mock_sessions.score` 直接存加权分，旧会话不受影响 ✓

### 2. 模型层
- `QuizRepository.compositeTemplate` / `compositePoints` 为公开 static const，UI 可直接引用 ✓
- 修复过程中发现并规避：Dart 中 **mixin 的静态成员不随 class 暴露**，常量必须定义在类本体（已修正，analyze 通过）

### 3. 计分正确性
- 满分计算：加权模式按题型分值求和（=150），结果弹窗显示"得分：98 / 150" ✓
- 多选 2 分 partial=1；简答 10 分 partial=5；单选/填空 1 分无 partial（全对/全错）✓
- 简答沿用要点命中判分（`grading.dart`），与刷题模式一致 ✓

### 4. 流程/交互
- 排题页保证至少展示 ~0.9s（`Future.wait` 并行抽题+延时），避免毫秒闪跳 ✓
- 抽完 `pushReplacement` 进考试页，返回键回到列表页 ✓
- 倒计时 180 分钟，到时自动交卷；交卷防重入（`_submitting`/`_finished`）✓
- 68 题答题卡网格复用 ✓

### 5. 边界/异常
- 某科某题型题量不足 → 第二轮补足，卷面数量不塌 ✓
- 极端情况全库不足 → 按实际可得抽，不报错、可作答 ✓
- 部分科目未导入 → 文学史配额由补足逻辑用现汉/古汉题填充，卷面仍 68 题可考 ✓
- 排题失败 → 错误态 + 重试按钮 ✓

### 6. 体验/产品
- 综合卷入口列表页恒置顶，不受 `bankId` 过滤影响 ✓
- **历史成绩标注满分**（本轮已修复：显示"最近 98 / 150"）✓

## 四、建议后续项（按优先级）

1. **【推荐】交卷逐题回顾**：结果页 → 逐题清单（题干/我的答案/正确要点/对错），解决 P1-2。需在 `submitMockSession` 或 UI 侧存每题作答快照。
2. **【可做】多选补充**：现汉+古汉多选池合计仅 10 道，是随机卷最短板块；后续按"语言类多选"方向补题可根治重复率。
3. **【低优】首页计数 + 补足标注 + AppLog**：三项小优化可随下次版本一并处理。
