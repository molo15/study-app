# 题库恢复与扩充规划案（v1.0）

> 日期：2026-08-27 · 触发：P1"整体重出基础题"误伤了大量仅需调整选项顺序即可修复的旧题，
> 现按用户决策改为「保留 + 修复 + 扩充」，不再删除重出。

## 1. 问题复盘（数据）

| | 旧版 v0.9.1 | 当前 v0.11.0 | 差异 |
|---|---|---|---|
| 基础题 | 4025 | 1146 | **-2879（被整体替换）** |
| 测试题 | 1014 | 1209 | +195（保留 + 增补） |
| 合计 | 5039 | 2355 | -2684 |

根因：P1 按"新出题规则重出基础题"时，把旧版 4025 道基础题**整体替换**为 1146 道新题
（每知识点 1-2 道直问直答），而非"保留 + 修复"。经核实（以现代汉语为例）：旧版 1065 道
基础题 id 与新版 **0 交集**，全部被替换。

用户判定：旧基础题的大部分问题（如"连着选 A"）**只需选项洗牌即可修复**，内容有效，
应恢复而非删除。

## 2. 恢复与扩充方案

### 2.1 核心原则（写入质量门禁）

1. **只洗牌，不删除**：选项顺序问题 → 洗牌 + answer 文本重算；绝不因"连着选 A"删题
2. **坏题定向修**：只有"答案错误 / 解析错误 / 题干残缺"的真坏题才进 rewrite 名单定向修复
3. **扩充以素材为源**：新增基础题严格基于私人笔记 + 用户提供题库参考，禁止凭空编造
4. **强去重兜底**：新旧合并后按题干归一化去重，重复题只保留质量高的一版

### 2.2 阶段划分

| 阶段 | 内容 | 输入 | 产出 | 验证 |
|---|---|---|---|---|
| **R1 恢复旧基础题** | 从归档包提取 4025 道旧基础题，合并回 | `legacy_banks_backup/*.bak4` | 合并题库（旧基础 + 新基础 + 测试） | 恢复数 = 归档数；id 无冲突 |
| **R2 全局选项洗牌** | 所有选择题选项洗牌 + v4 answer 文本重算（修复"连着选 A"） | 合并题库 | 洗牌后题库 | 答案位置分布 ≈ 均匀；answer 校验通过 |
| **R3 质量修复** | 解析缺口补全（复用 P1 解析重出成果）+ rewrite 名单定向修坏题 | `out/reports/rewrite_*.json` | 修复后题库 | 解析覆盖率 100%；坏题清零 |
| **R4 按素材扩充** | 每知识点基础题扩到 3-5 道（同知识点不同问法） | 私人笔记 + 用户发题库参考 | 扩充题 | 覆盖率报告：每知识点 ≥3 道 |
| **R5 去重 + 打包** | 强去重 → v4 打包 → 部署 | 扩充后题库 | **v0.12.0** 5 库 | verify_v012 全绿 + 覆盖率报告 |

## 4. 质量门禁（打包校验表，任一不过即打回）

- G1 解析覆盖率 100%（无空解析）
- G2 选择题答案位置分布均匀（不出现"连着选 A"）
- G3 强去重：同库内题干归一化去重 = 0 重复
- G4 answer 文本编码 → App 映射回 key 无异常（verify 脚本）
- G5 选择题 options：key 唯一、text 非空（0 异常）
- G6 每知识点基础题 ≥3 道（覆盖率报告）
- G7 知识点树 / overviews 完整（formatVersion=4）
