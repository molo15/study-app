## 2. 已实施项详细验证

### 2.1 PWA 离线缓存（原 P1）— 完整实施 ✅

#### 2.1.1 自定义 Service Worker

**文件**：`app/web/sw.js`（108 行）

实现了完整的 PWA 离线缓存策略：

| 策略 | 适用资源 | 实现位置 |
|---|---|---|
| **App Shell 预缓存** | index.html、main.dart.js、flutter.js、canvaskit、中文字体、sqlite3.wasm、图标、manifest 等 20 个核心资源 | `install` 事件（第 41-55 行） |
| **缓存优先**（Cache First） | 静态资源（js/wasm/woff2/ttf/png/json/zip 等） | `fetch` 事件（第 94-107 行） |
| **网络优先**（Network First） | 页面导航（index.html） | `fetch` 事件（第 76-91 行） |
| **离线兜底** | 全部 miss 时返回缓存首页或 503 提示 | 第 84-87 行 |

预缓存清单设计合理：
- 包含 `sqlite3.wasm` + `sqflite_sw.js`（Web 端数据库引擎，离线必需）
- 包含 `NotoSansSC-subset.woff2`（中文字体子集）
- 包含 `canvaskit/chromium/canvaskit.wasm`（仅实际使用的 chromium 变体，不缓存其他 5 个变体，避免浪费）
- **不预缓存题库 zip**（体积大，由运行时缓存优先策略首次访问后自动缓存）

#### 2.1.2 SW 注册入口

**文件**：`app/web/flutter_bootstrap.js` 第 47-56 行

```javascript
// PWA 离线缓存：load 完成后注册自定义 Service Worker（sw.js），不阻塞首帧。
if ('serviceWorker' in navigator) {
  window.addEventListener('load', function () {
    navigator.serviceWorker.register('sw.js').catch(function (err) {
      console.warn('Service worker registration failed:', err);
    });
  });
}
```

- 在 `window.load` 后注册，**不阻塞首帧**（符合原报告 1.5 节"首屏性能"建议）
- 有错误捕获，注册失败不影响 App 运行

### 3.1 布局结构差异化 — 部分实施 ⚠️

原报告 2.5 节建议：
> 引入断点系统：compact 单列 / medium 双栏或宽卡片 / expanded 侧边导航 + 多栏
> 平板 / 桌面差异化：大屏采用侧边导航替代底部 dock、题库双栏列表

**实际情况**：
- ✅ 断点系统已建，宽度分档已生效
- ✅ 首页题库卡片宽屏两列
- ❌ **底部导航栏（GlassTabBar）在所有档位均为底部 dock**，未在 expanded 档位切换为侧边导航（NavigationRail）
- ❌ 章节列表页（`ChapterOverviewListPage`）、题目列表页等仍为单列，未利用宽屏做双栏
- ❌ 答题页（`practice_page.dart`）仍为手机单列布局，宽屏下题目和选项区域较宽（920px），行偏长

**影响**：平板/桌面用户的信息密度仍偏低，大屏优势未充分利用。但当前"宽度分档+首页两列"已比原报告描述的"固定 560 居中"有明显改善，属于渐进式适配。

**建议**：这是 P2 级改进，非阻断项。可在后续迭代中为 expanded 档位引入 `NavigationRail` 侧边导航，并将章节/题目列表改为双栏。

### 3.2 post_build_sw.py 未集成到自动化构建 — 新增风险 ⚠️

**现状**：
- `tools/post_build_sw.py` 存在且功能正确
- 构建产物 `build/web/sw.js` 中 BUILD_ID 已被替换（说明手动运行过）
- **但项目中没有 build.bat / build.sh / Makefile / CI 配置**来自动调用此脚本
- `docs/` 中没有任何文档说明构建 Web 时需要运行 `python tools/post_build_sw.py`

**风险**：
如果开发者（或未来的 CI）直接运行 `flutter build web --release` 后部署，忘记运行 `post_build_sw.py`，则：
- `build/web/sw.js` 中 `BUILD_ID = '__BUILD_ID__'`（占位符未替换）
- 缓存命名空间为 `quiz-shell-__BUILD_ID__`，所有构建版本共享同一个缓存名
- 发布新版本后，旧缓存不会被清理（因为 BUILD_ID 没变），用户可能命中旧版本资源
- 这是一个**静默失败**：App 仍能运行，但缓存版本化机制失效

**建议**（二选一）：
1. **创建构建脚本**：`app/build_web.bat`（或 .ps1），内容为 `flutter build web --release && python tools/post_build_sw.py`，并在 docs 中说明
2. **集成到 flutter build**：通过 `dart-define` 或自定义 builder 在构建后自动运行（较复杂）

报告日期与今天同为 2026-09-01，说明报告写于修复之前。建议在原报告顶部标注"本报告问题已修复，详见实施情况审查报告"，或更新原报告内容。

### 4.2 两个 Service Worker 共存于构建产物

`build/web/` 中同时存在 `flutter_service_worker.js`（空壳）和 `sw.js`（自定义）。虽然只有 `sw.js` 被注册，但空壳文件仍会被部署到服务器。这不影响功能，但可考虑在 `.gitignore` 或构建后清理中移除空壳文件以减少混淆。

### 4.3 运行时缓存也带 BUILD_ID

`RUNTIME_CACHE = 'quiz-runtime-' + BUILD_ID`，意味着每次构建后运行时缓存（题库 zip 等）也会被清空。由于题库 zip 文件名自带版本号（如 `bank-xiandai-hanyu-v0.14.0.zip`），清空后重新缓存不会导致错误，但会增加一次全量下载。可考虑将运行时缓存改为不带 BUILD_ID，仅在资源 URL 变化时自然更新。低优先级。
