### P1 · 重要缺陷

#### P1-1 · 存档 appVersion 硬编码过时，跨端版本判断失真

- **证据**：`app/lib/data/quiz_repository_export.dart:41` — `const String kArchiveAppVersion = '1.2.0';`；但 `app/pubspec.yaml:19` — `version: 1.4.0+15`
- **影响**：导出存档的 `appVersion` 字段永远写 1.2.0，与实际版本脱节。若未来基于 appVersion 做存档兼容性判断（如"低于 1.3.0 的存档需迁移"），会全部误判。当前仅作展示用，影响有限但属于埋雷。
- **修复建议**：从 `pubspec.yaml` 构建时注入，或至少在发版时同步更新该常量。

#### P1-2 · 设置页「导出备份」文案与实际行为严重不符，会误导用户

- **证据**：`app/lib/ui/settings_page.dart:847-848` — ListTile title「导出备份」，subtitle「全部题目/作答/复习进度导出为 JSON 文件」；但实际调用 `repo.exportArchive()`（`quiz_repository_export.dart:114`），导出的是 **zip 压缩包**，且**只含用户状态、不含题目**（多端存档方案 §2.5 明确剔除题目）。
- **影响**：用户以为导出了题目+作答的 JSON 备份，实际拿到的是不含题目的 zip。跨端迁移时若用户以为存档包含题库，可能在新设备上因题库未内置而出现"记录匹配不到题"的困惑。
- **修复建议**：subtitle 改为「导出做题记录/复习进度/背题进度为 zip 存档（不含题库）」。

#### P1-3 · 现代汉语 71 题、古代汉语 42 题无解析，占比偏高

- **证据**：全量题库元数据扫描：
  - 现代汉语：752 题中 **71 题无解析**（9.4%）
  - 古代汉语：901 题中 **42 题无解析**（4.7%）
  - 其余三科（现文/当文/古文）：0~4 题无解析
- **影响**：考研刷题 App 的核心价值是"做完题知道为什么对/错"。现汉作为主科（综合卷占比最高 26 题），近 10% 题目无解析，用户答错后无法获得反馈，直接损伤学习效果。
- **修复建议**：优先补全现汉 71 题解析；古汉 42 题次之。可批量生成后人工审核。

#### P1-4 · 中国现代文学史 5 题题干前 50 字重复，需确认是否为真重复

- **证据**：全量扫描 `bank-zhongguo-xiandai-wenxue-v0.14.0.zip`，1114 题中 5 题题干前 50 字完全相同。其余各科 0~1 题。
- **影响**：若为真正的重复题（非变式题），违反设计理念 §2.1「变式重复直接删——出题目的是覆盖记忆点，不是堆量」。现文是题量最大的科（1114 题），重复题会稀释复习效率。
- **修复建议**：导出这 5 题的完整题干和 id，人工判断是真重复还是合理变式；真重复则删除并更新题库包版本。

### P2 · 改进建议

#### P2-1 · 项目进度文档严重过时，与实际状态脱节

- **证据**：`docs/PROJECT_PROGRESS_2026-08-24.md` 记录：题库 5037 题 / 内置包 v0.9.1 / 版本 1.0.0；实际：4509 题 / v0.14.0 / 版本 1.4.0+15。该文档距今已 8 天，期间经历了多端存档（v1.1~v1.6）、Web 适配、题库 v0.14.0 等重大变更。
- **影响**：新开发者或审查者以该文档为事实基准会被误导。文档中"已知问题"清单（如模拟器验证未完成）也可能已过时。
- **修复建议**：更新 PROJECT_PROGRESS 至当前版本，或在文档顶部标注"已过时，以多端存档方案 v1.6 和 git log 为准"。

#### P2-2 · 审查提示词自身存在事实偏差

- **证据**：`docs/审查提示词-分对话审查-v1.0.md` 第 23 行声称"题型含 单选/多选/填空/简答（论述已并入简答）"——实际题库有 **5 种题型，含 true_false 判断题**（现汉 8 题、古汉 6 题、现文 39 题、当文 4 题、古文 6 题，共 63 题）。第 29 行声称"12 个测试文件"——实际 **13 个**。
- **影响**：审查者基于错误前提可能漏查判断题相关逻辑，或对测试覆盖度产生误判。
- **修复建议**：更新提示词为 5 种题型 + 13 个测试文件。

#### P2-3 · Web 端自动存档用 localStorage base64，大数据量下有容量风险

- **证据**：`app/lib/services/archive_store_web.dart:19-28` — 自动存档序列化为 base64 存入 localStorage。localStorage 容量上限约 5MB，base64 膨胀 33%。若用户做题记录量大（如 4509 题各做数次，answer_logs 可能上万条），单份存档 base64 后可能超过 5MB。
- **影响**：容量不足时代码会先清空旧存档再写入（第 24-26 行），但如果单份就超限，清空后仍写不进去，自动存档静默失败（catch 后无用户提示）。Web 端用户可能丢失数据而不自知。
- **修复建议**：① 写入失败时给用户可见提示（"存档过大，请导出手动备份"）；② 长期考虑迁移到 IndexedDB（容量远大于 localStorage）。

#### P2-4 · 判断题选项 key 用中文「正确/错误」，与其他题型 A/B/C/D 不统一

- **证据**：`app/lib/data/seed_loader.dart:140-149` — `_ensureTrueFalseOptions` 强制补齐选项 key 为 `'正确'` 和 `'错误'`。其他题型选项 key 为 A/B/C/D。
- **影响**：`_userAnswerText`（`quiz_repository_mock.dart:153`）和 `mockSessionReview`（第 274 行）按 `、` 分割还原用户作答，中文 key 不含 `、` 所以能正常工作。但如果未来有逻辑假设选项 key 为单字符（如 `_mapChoiceAnswer` 第 178 行 `a.length == 1` 判断），判断题会走"正确项文本映射"分支而非"已是 key"分支，虽然结果正确但路径不一致。
- **修复建议**：低优先级，当前逻辑兼容。若追求统一可改为 key='A'/'B'，text='正确'/'错误'。

#### P2-5 · 综合卷中「中国古代文学史」仅 3 题且多选 0 题，占比过低

- **证据**：`app/lib/data/quiz_repository.dart:116-121` — compositeTemplate 中古代文学史：单选 2 + 多选 0 + 填空 1 + 简答 0 = 3 题。综合卷总分 150 分中该科仅占 3 分（2%）。
- **影响**：设计理念 §2.4 要求"主次分明"，现汉+古汉为主是合理的。但古代文学史 3 题中无多选、无简答，题型覆盖不全，用户在模拟卷中几乎不会遇到该科的主观题。
- **修复建议**：可接受为设计取舍（主科优先）。若想提升该科存在感，可加 1 道简答（总分变为 160，需重新配平分值）。

#### P2-6 · `archive_store_io.dart` 第 14 行格式不规范

- **证据**：`app/lib/services/archive_store_io.dart:14` — `final String? _basePath;  Future<Directory> _dir() async {` 两个声明挤在同一行，缺少换行。
- **影响**：不影响功能，analyze 也不报错，但不符合 Dart 代码规范。
- **修复建议**：换行分开。

## 3. 亮点（值得保留的设计）

1. **FSRS 调度与作答日志单事务原子写入**（`quiz_repository_srs.dart:19-44`）：`logAnswerAndSchedule` 在一个 transaction 内同时写 answer_logs 和 card_scheduling，任一失败整体回滚，杜绝"有日志无调度"或"调度双计"。这是数据一致性的关键防线。

2. **条件编译架构干净，调用方零感知**：四组平台差异（`archive_store` / `export_helper` / `app_background_image` / `db_factory`）均通过 `dart.library.js_interop` 条件导出切换，同名类/函数在 io 和 web 端行为不同，但 UI 层和业务层完全无感知。Web 适配（Phase 2.2）的侵入性被控制到最低。

3. **题库导入三层保护**：① 幂等 upsert + 软归档（不在新包中的题不物理删除）；② `user_edited` 标记保护用户本地修改（更新时跳过 REPLACE）；③ `idSchema` 变化时整库重建（避免旧 id 题堆积且学习记录无法匹配）。数据迁移设计考虑了多种边界情况。

4. **存档 v3 与题库解耦 + 事务回滚保护**（`quiz_repository_export.dart:228-353`）：存档只含用户状态、不含题目，避免与题库包管理冲突；导入时在事务内先清空再写入，任何一步失败整体回滚，杜绝"损坏文件静默清空数据"。v2 旧备份兼容（忽略题目字段）。

5. **错题本移出逻辑严谨**（`quiz_repository_srs.dart:248-274`）：以「最近一次任意模式的答错」为时间界，只统计其后 `wrong_rework` 模式的连续答对，阈值 2 次自动移出。避免了"重归错题本后 1 次答对就达旧阈值移出"的漏洞，也避免了 learn/mock 模式的正确/错误污染计数。
