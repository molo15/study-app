## 3. 问题清单

### P1 · 重要缺陷

#### P1-1 · post_build_cleanup.py 未在本次构建中运行，死资源仍存在

- **证据**：构建产物中仍存在以下应被清理的文件：
  - `canvaskit/**/*.symbols`：6 个调试符号文件，总计 8.18 MB
  - `assets/assets/fonts/NotoSansSC-subset.ttf`：7.1 MB（Web 端只用 woff2，ttf 是死资源）
  - `flutter_service_worker.js`：0.8 KB（Flutter 注销空壳，未被注册）
- **影响**：部署体积比清理后多 15.3 MB（65.57 MB → 50.3 MB）。.symbols 和 ttf 不会被浏览器请求，但占用部署空间和部署时间。
- **根因**：构建流程只运行了 `flutter build web` → `post_build_sw.py` → `precompress.py`，未运行 `post_build_cleanup.py`。
- **修复建议**：创建统一的 `build_web.bat` 串联所有步骤：
  ```bat
  @echo off
  flutter build web --release
  python tools/post_build_sw.py
  python tools/precompress.py
  python tools/post_build_cleanup.py
  ```

---

### P2 · 改进建议

#### P2-1 · precompress.py 未压缩 NOTICES 文件（1.34 MB 纯文本）

- **证据**：`precompress.py:12` 的 EXTS = `{'.wasm', '.js', '.json', '.css', '.html', '.txt', '.svg'}`。`assets/NOTICES` 文件无扩展名，不在压缩列表中，因此未生成 `.gz`。
- **影响**：NOTICES 是 1.34 MB 的纯文本开源许可证声明，gzip 后约 300-400KB，可减少 1MB 传输。虽然 NOTICES 不是首屏关键资源，但用户浏览器在加载字体时可能触发 NOTICES 请求（Flutter 框架行为）。
- **修复建议**：在 `precompress.py` 中增加对无扩展名文本文件的处理，或直接将 NOTICES 加入压缩列表（按文件名匹配）。

#### P2-2 · 缺少统一的构建脚本，构建步骤易遗漏

- **证据**：当前有 4 个构建后脚本（post_build_sw.py、precompress.py、post_build_cleanup.py、gzip_server.py），但没有统一的入口脚本。本次构建就遗漏了 post_build_cleanup.py。
- **影响**：手动运行多个步骤容易遗漏，导致构建产物不一致（如本次 .symbols 和 ttf 未清理）。
- **修复建议**：创建 `app/build_web.bat`（Windows）和 `app/build_web.sh`（Linux/Mac），串联所有构建后步骤。

#### P2-3 · 题库版本不一致：三科 v0.14.1，两科 v0.14.0

- **证据**：
  - v0.14.1：现代汉语、古代汉语、中国现代文学
  - v0.14.0：中国当代文学、中国古代文学
- **影响**：可能是正常的分批更新（不同科目更新频率不同），但需确认是否为有意状态。若当文和古文有未合并的更新，可能导致用户看到的题目版本不一致。
- **修复建议**：确认当文和古文是否有 v0.14.1 待发布；若为有意分批更新则无需处理，建议在题库管理文档中记录各科目版本。

#### P2-4 · .gz 文件占用部署空间，但需服务器配置才能生效

- **证据**：24 个 .gz 文件总计 12.6 MB。这些文件只有在服务器配置了 `gzip_static`（Nginx）或等效功能时才会被使用。如果服务器不支持 .gz 静态文件，这些文件就是死资源。
- **影响**：如果部署到不支持 gzip_static 的服务器（如简单的 Python HTTP server、某些静态托管平台），.gz 文件不生效，且占用 12.6MB 部署空间。
- **修复建议**：① 确认部署服务器支持 gzip_static（Nginx）或 brotli_static；② 项目已提供 `gzip_server.py` 用于本地测试，生产部署需配置对应服务器模块；③ 若部署平台不支持静态预压缩，可考虑不运行 precompress.py，依赖服务器动态 gzip。

### P3 · 低优先级 / 提示

#### P3-1 · base href = "/"，假设根路径部署

- **证据**：`build/web/index.html:17`：`<base href="/">`
- **影响**：如果部署到子路径（如 `https://example.com/quiz/`），所有相对路径资源会 404。需要用 `flutter build web --base-href "/quiz/"` 重新构建。
- **修复建议**：部署前确认目标路径。根路径部署则 OK；子路径需重新构建。

#### P3-2 · index.html preload 的 canvaskit 变体可能与实际加载的变体不一致

- **证据**：`index.html:40-41` preload 了 `canvaskit/chromium/canvaskit.js` 和 `.wasm`。但 Flutter 会根据浏览器能力选择不同变体（chromium / full / webparagraph / skwasm / skwasm_heavy / wimp）。
- **影响**：如果浏览器实际使用的不是 chromium 变体，preload 的资源就是浪费（但不会阻塞，注释已说明"仅作预热不阻塞"）。Chromium 内核浏览器（Chrome/Edge）占市场份额约 70%+，所以大多数用户能命中 preload。
- **修复建议**：可接受为合理的性能权衡。若想更精确，可根据 user-agent 动态注入 preload，但复杂度高、收益有限。

#### P3-3 · 清理后部署体积估算

当前 65.57 MB，执行以下操作后：
- 运行 post_build_cleanup.py：-15.3 MB（.symbols 8.18 + ttf 7.1 + 空壳SW 0.001）
- 压缩 NOTICES：-约 1 MB（传输时，不占部署空间）
- **清理后部署体积：约 50.3 MB**（含 .gz 文件）
- **若不部署 .gz 文件（服务器动态压缩）：约 37.7 MB**

## 5. 亮点（值得保留的构建配置）

1. **完整的构建工具链**：4 个脚本覆盖构建指纹替换、预压缩、死资源清理、本地 gzip 测试，工程化程度高。

2. **.gz 预压缩**：24 个文件，压缩率 39.1%，配合 nginx gzip_static 零 CPU 直发。main.dart.js 仅 977KB，首屏加载大幅改善。

3. **index.html preload 优化**：4 个关键资源（main.dart.js、canvaskit chromium js/wasm、NotoSansSC woff2）在 HTML 解析阶段就开始并行下载，与 flutter_bootstrap.js 的解析/注入并行，减少串行等待。

4. **canvaskit 本地化**：`canvasKitBaseUrl: "canvaskit"`，免 Google gstatic CDN，国内更快更稳。

5. **字体加载优化**：不放入 FontManifest（避免 17.7MB VF 预下载），改用 FontLoader 按需加载子集 woff2 (2.9MB)，配合 index.html preload 并行下载。

6. **PWA Service Worker**：App Shell 预缓存（20 个核心资源）+ 静态资源缓存优先 + 导航网络优先 + 离线兜底。版本化缓存（BUILD_ID = main.dart.js SHA-256 前缀），运行时缓存不带 BUILD_ID（避免每次发版清空题库缓存）。

7. **precompress.py 智能压缩**：仅当压缩后更小时才生成 .gz，避免对已压缩格式（woff2/zip/png）无效压缩。
