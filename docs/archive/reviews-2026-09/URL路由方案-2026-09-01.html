一、目标与收益

重构前：Navigator 1.0 不写浏览器历史，URL 恒为首页（/?v=...），分享/收藏只能开首页，刷新必回根页，前进键无效。

重构后（本轮落地）：

  • ✓ 分享/书签直达内页——二级页（科目/章节/错题本/模拟考/题库管理）有独立 URL
  • ✓ 刷新保持页面位置——刷新深链 URL 后停留原页
  • ✓ 浏览器前进/后退有效——历史逐级对应 URL 与页面
  • ✓ iOS 主屏 PWA 深链——hash 策略下零服务器配置，主屏图标直开可带路径
  • ✓ 移动打包复用——路由表与平台解耦，Android/iOS 包同构

三、技术方案

  • go_router 18 + 嵌套路由：RootPage 为根 route，二级页为子 route（嵌套保留 RootPage 在栈底，返回不重建父页面）。
  • 导航用 context.go() 而非 context.push()：go_router 的 push 是命令式导航，默认不更新 URL（官方设计）；go 才同步 URL。嵌套 + go 组合实现「URL 同步 + 父页面保留」。
  • hash 策略：Flutter Web 默认，静态托管零配置（无需 SPA fallback）；深链 #/bank/... 不触发服务器 404。sw.js 兼容（导航网络优先 + 离线回退 index.html，hash 不参与请求）。
  • bankId 实际格式：bank-gudai-hanyu 等（带 bank- 前缀）；章名经 URL 编码（%E4%BF%AE%E8%BE%9E），go_router 已自动解码 path 参数。
  • 改动面：main.dart（MaterialApp → MaterialApp.router）+ 新增 router.dart + 6 个页面文件导航点改造；数据层 / SRS / 存档 / 主题 / PWA 封装 0 改动。

五、边界与已知 tradeoff

  • 浏览器后退在会话页（刷题/考试）：直接回上级 URL，不弹「继续上次进度？」确认框（URL 变化触发 go_router 强制重匹配，PopScope 仅拦截应用内返回）。进度已自动存档，重进可续，仅少一次确认。应用内 AppBar 返回仍走 PopScope 弹窗。
  • 深链打开不存在的章节：章节页显示空态（题库未导入或链接失效），不崩溃。
  • 历史条目含 ?v= 测试参数时后退会跨版本跳转（本地测试特征，生产无此参数）。
  • 若将来切换 path 策略（usePathUrlStrategy），需配服务器 fallback（nginx try_files $uri /index.html）；当前 hash 策略无需。

六、部署注意事项

  • 静态托管零配置：hash 策略下任意静态服务器（nginx / GitHub Pages / 对象存储）直接可用。
  • sw.js 兼容：导航网络优先 + 离线回退 index.html，hash 路由无冲突；构建后需重跑 python tools/post_build_sw.py 更新 BUILD_ID。
  • iOS 主屏 PWA：主屏图标打开即根页，可在 Safari 地址栏粘贴分享的 #/bank/... 深链直达。
