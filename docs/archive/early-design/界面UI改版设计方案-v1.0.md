# 考研刷题 App 界面 UI 改版设计方案

> 版本：v1.0
> 日期：2026-08-17
> 适用平台：Android 手机，兼容平板与横屏
> 技术栈：Flutter + Material 3
> 设计目标：在不改变答题、判题、提交、题库、错题本、FSRS、统计和模拟卷业务逻辑的前提下，重构界面层级、视觉系统、交互反馈与状态展示。

---

## 1. 改版结论

当前 App 已具备完整的功能骨架和基础视觉风格：

- Material 3 主题系统；
- 毛玻璃 AppBar；
- 圆角卡片；
- 沉浸式 edge-to-edge；
- 首页、题库、刷题、错题本、统计、设置等主要页面；
- 自定义主色、背景图、透明度、深色模式；
- 计时器、题型反馈和题库专题入口。

但当前界面仍然偏向“多个功能卡片依次排列”，没有形成清晰的学习任务优先级。主要问题不是颜色或圆角不足，而是：

1. 首页入口过多，缺少明确的“现在该做什么”；
2. 题库页信息密度高，但重点章节、随机刷题、论述题专题层级不够清晰；
3. 刷题页仍是普通表单式布局，题干、作答区、反馈区的节奏不够强；
4. 统计页有图表，但缺少可执行的学习结论；
5. 错误、空数据、加载状态没有统一组件；
6. 小屏、横屏、大字体和深色背景图场景存在溢出或对比度风险；
7. 底部导航、卡片、图标容器在不同页面重复实现，视觉细节容易漂移。

改版的核心方向是：

> **保留沉浸式和毛玻璃风格，但将 App 从“功能展示型”改为“学习任务驱动型”。**

---

## 2. 不变项与改动边界

### 2.1 必须保留

以下业务逻辑和数据行为不做改变：

- 题库导入、读取、章节分组和题量统计；
- 单选、多选、判断、填空、简答的答题流程；
- `gradeQuestion` 判题逻辑；
- 提交、四档评分和 FSRS 调度；
- 错题本归集与移出规则；
- 模拟卷组卷、交卷和成绩记录；
- 学习统计 SQL、累计用时和作答记录；
- 论述题专题、重点章节合集、整本随机刷题入口；
- 本地优先和离线运行方式。

### 2.2 本次只改界面层

允许修改：

- 页面布局和信息层级；
- 颜色、字体、间距、圆角、阴影和图标；
- 加载、错误、空状态和成功反馈；
- 触摸区域、语义标签、焦点反馈；
- 页面转场和底部导航视觉；
- 设置页主题编辑体验；
- 刷题页题干、选项、计时器和解析卡的视觉呈现。

不允许为了 UI 改动：

- 数据库表结构；
- 判题条件；
- 作答日志字段含义；
- 题库查询条件；
- 统计计算公式；
- FSRS 参数和调度流程。

## 3. 当前 UI 问题审查

### 3.1 全局结构问题

#### 3.1.1 页面层级可用，但缺少统一页面容器

当前首页、统计页、设置页各自包含 `Scaffold + GlassAppBar`，外层 RootPage 也有 Scaffold。虽然功能正常，但会带来：

- AppBar 高度和 inset 处理容易不一致；
- 页面之间的背景、滚动和底部安全距离容易出现细微差异；
- 通用错误态、空态、页面标题无法统一复用。

**设计处理：**保留现有导航结构，新增统一的 `AppPageShell`、`AppSectionHeader`、`AppStateView`，逐步替换重复 Scaffold 内容，不一次性改动 RootPage 业务结构。

#### 3.1.2 底部导航隐藏时仍可能命中点击

RootPage 使用 `AnimatedSlide + AnimatedOpacity` 隐藏底部导航，但透明不等于不可点击。动画中或边缘位置可能出现幽灵点击区域。

**设计处理：**隐藏状态增加 `IgnorePointer(ignoring: true)`，显示时恢复点击；不改变导航逻辑。

#### 3.1.3 缺少平板和横屏最大内容宽度

目前页面普遍使用固定 16dp 左右边距，平板上会显得内容过宽，横屏时阅读路径过长。

**设计处理：**新增统一内容容器：

```text
手机：左右 16dp，最大宽度不限制
平板/横屏：内容最大宽度 720dp，居中显示
大屏双栏：仅统计页、设置页和题库页考虑双栏，不改变刷题页业务流程
```

### 3.2 首页问题

当前首页包含：今日概览、今日复习、错题本、模拟考试、题库列表、顶部学习提示和错题 Badge。

主要问题：

- 今日任务和题库列表视觉权重接近；
- “待复习 / 新题 / 错题”是数字，但缺少行动解释；
- 顶部“今日 N 题 · 正确率 · 连学 N 天”在窄屏可能挤压标题和错题按钮；
- 错题本在顶部和正文各出现一次，入口重复；
- 模拟考试为空时整个模块消失，用户不知道该功能存在还是暂无试卷；
- 题库卡片只有名称和题量，缺少最近学习进度；
- 首页没有明确的主行动按钮。

#### 首页改版结构

```text
顶部 AppBar
  左：页面标题“考研刷题”
  右：简化后的今日状态图标/菜单

今日任务区（主视觉区）
  今日待复习：N 题
  今日新题：N 题
  错题待巩固：N 题
  主按钮：开始今日复习
  无任务时：今日任务已完成 + 刷新题按钮

快捷入口区
  错题本
  模拟考试
  论述题专题/最近使用入口（如果存在）

题库区
  题库名称
  总题数
  已答进度
  最近一次学习章节
  右侧进入箭头
```

#### 首页视觉规则

- “开始今日复习”是页面唯一主按钮；
- 错题本和模拟考试使用较轻的次级卡片；
- 顶部今日状态不再使用长文本胶囊，改为 `IconButton + Tooltip` 或短文本；
- 题库列表支持一行标题、两行辅助信息，题量使用小号弱化文本；
- 没有模拟卷时显示轻量空状态：“暂未配置模拟卷”，不要直接隐藏所有上下文。

### 3.3 题库详情页问题

当前 BankPage 具有：题库概览、重点章节合集、整本随机刷、编/章树、论述题专题。

主要问题：

- 重点章节、整本随机和论述题专题都是同级 Card，缺少主次；
- 编/章树使用多个 ExpansionTile，页面视觉重复；
- 章节题量只展示数字，不能帮助用户判断学习优先级；
- 论述题专题虽然已修复为单一入口，但视觉上仍像普通章节；
- 题库版本信息占用首屏空间，但对日常学习不是主要信息。

#### 题库页改版结构

```text
顶部：题库名称 + 轻量版本信息

题库概览卡
  总题数
  已完成题数
  掌握度/作答进度（若已有数据则展示）

推荐入口区
  重点章节合集       主推荐
  整本随机刷         次推荐
  论述题专题         独立专题样式

章节目录
  编标题
  章节行：章节名 + 题数 + 进入按钮
  论述题专题不再出现在普通编目录中
```

#### 题库入口视觉区分

| 入口 | 定位 | 视觉等级 | 图标方向 |
|---|---|---|---|
| 重点章节合集 | 高优先级学习路径 | 主卡片 | 星标/目标 |
| 整本随机刷 | 灵活练习 | 次卡片 | 随机 |
| 论述题专题 | 特殊题型专题 | 专题卡片 | 论坛/文档 |
| 普通章节 | 目录导航 | 列表行 | 文档/文件夹 |

论述题专题应使用独立的浅色主题背景或左侧色条，避免看起来像普通章节重复入口。

### 3.4 刷题页问题

刷题页是整个 App 的核心，但当前页面仍然是“题型徽章 + 章节 + 题干 + 选项 + 提交/评分”的纵向堆叠。

主要问题：

- 题干虽然已加大，但阅读区域和选项之间缺少明确的节奏；
- 选项反馈主要依赖边框颜色，色弱用户不容易区分；
- 题型、章节、进度都在同一行，小屏和大字体下容易挤压；
- 提交、评分、解析区域在不同题型下变化较大，缺少稳定锚点；
- 计时器显示与隐藏已实现，但视觉上还应更弱化，避免变成考试倒计时感；
- 完成页内容居中，在小屏和大字体下有溢出风险；
- 解析卡、参考答案、来源信息的层级不够清晰。

#### 刷题页改版结构

```text
顶部 AppBar
  左：返回
  中：题型/模式
  右：计时器（按设置开关显示）
  下方：细进度条

题目元信息
  题号 / 总题数
  题型标签
  章节标签（弱化）

题干区
  大字号正文
  更宽行距
  题干与选项之间 20~24dp

作答区
  选择题：整行可点，选中有填充色、边框、图标三重反馈
  填空/简答：输入框 + 明确完成按钮

操作区
  提交按钮固定在内容末尾
  评分按钮统一高度和间距

反馈区
  结果标签
  正确答案/参考答案
  解析
  来源
```

#### 刷题页视觉规则

- 题干正文建议 20~22sp，行高 1.55~1.7；
- 题号和题型标签使用 `labelMedium`，章节使用 `bodySmall`；
- 选项最小高度 52dp，点击区域覆盖整行；
- 选中态同时使用：背景填充、边框、勾选图标，不能只依赖颜色；
- 正确态使用“正确”图标和文本；错误态使用“错误”图标和文本；
- 计时器使用弱化灰色 `MM:SS`，不使用醒目主色；
- 评分按钮统一为 48dp 以上高度；
- 解析卡按“结果 → 答案 → 解析 → 来源”固定顺序；
- “提交”按钮保持现有业务和主按钮行为，只调整容器宽度、间距和禁用态。

#### 刷题状态

必须统一以下状态：

1. 加载中：题库加载骨架或居中进度指示器；
2. 无题目：图标 + “该范围暂无题目” + 返回/选择其他章节按钮；
3. 作答中：选项可操作，提交按钮按原规则启用/禁用；
4. 已提交：答案不可编辑，展示反馈卡；
5. 评分中：评分按钮显示 loading，防止重复操作；
6. 页面退出：停止计时，不保留后台 Timer；
7. 完成：显示完成统计，并提供“返回题库”和“再刷一次”入口。

### 3.5 统计页问题

当前统计页有总览、近 7 日图表、题型饼图、作答结果饼图、章节掌握度。

主要问题：

- 四个总览指标在窄屏横向排列，容易拥挤；
- 图表展示数据，但没有转化为学习建议；
- 饼图适合看比例，不适合比较章节或时间趋势；
- “累计用时”单位是分钟/小时，但缺少“本周学习时长”或趋势解释；
- 章节列表可能很长，视觉重点分散；
- 空状态仅在章节区域处理，整个统计页没有首次使用引导。

#### 统计页改版结构

```text
总览
  今日做题
  总做题
  正确率
  累计用时

学习趋势
  近 7 日做题量柱状图
  本周与上周对比（若数据可用）

薄弱环节
  错误率最高章节 Top 5
  题型正确率
  “去练习”按钮仅负责导航，不改变统计业务

题型分布
  使用横向条形图优先，饼图作为辅助

章节掌握度
  可折叠列表
```

统计页不新增业务计算时，先只做视觉重排：继续使用已有 `StudyStats` 字段，不改变 SQL 和统计定义。

---

### 3.6 设置页问题

当前设置页包含主题定制、记忆保持率、刷题计时开关、题库包、数据导出。

主要问题：

- 设置项按照开发功能分组，不完全符合用户认知；
- 主题定制进入后选项较多，缺少预览优先；
- 主题滑块可能在拖动过程中频繁持久化和触发全局刷新；
- 颜色选择器缺少语义标签和可访问性；
- `_message` 文本与 SnackBar 重复；
- 题库包和数据维护属于高级功能，应该折叠或放到“数据与存储”。

#### 设置页改版结构

```text
学习设置
  刷题页显示计时
  记忆保持率

外观设置
  主题定制
  深色模式
  背景图

数据与题库
  题库包管理
  导出备份
  恢复备份（如已有）

关于
  题库版本
  App 版本
```

“刷题页显示计时”保持现有标题和说明，使用标准 SwitchListTile，默认关闭，不改变底层计时。

主题定制页增加顶部实时预览卡，用户先看到效果，再调整参数；滑块建议在 `onChangeEnd` 或防抖后持久化。

## 4. 统一设计系统

### 4.1 视觉关键词

- 安静：减少大面积高饱和色；
- 清晰：主次对比明确；
- 学术：使用文档、章节、批注感的视觉隐喻；
- 专注：刷题页减少装饰；
- 可恢复：错误和空状态都给出下一步行动。

### 4.2 色彩角色

不取消用户自定义主色，但所有颜色先映射到语义角色：

```text
primary              主行动、选中态、进度
onPrimary            主行动文字
primaryContainer     今日任务、提示背景
secondary            专题/辅助入口
tertiary             随机练习、模拟卷
surface              页面表面
surfaceContainer     卡片表面
outline              边界和弱辅助信息
success              正确
warning              部分正确/提醒
error                错误/错题
```

规则：

- 正文禁止使用低对比度 `outline`；
- `outline` 只用于辅助信息和分割线；
- 选中、正确、错误不能只靠颜色，必须同时有图标或文字；
- 深色模式下背景图遮罩必须使用深色 overlay；
- 自定义主色生成后做前景/背景对比度检查，必要时自动选择深色或浅色前景。

### 4.3 字体层级

| Token | 建议 | 用途 |
|---|---:|---|
| displaySmall | 32sp / 700 | 完成页核心结果 |
| headlineSmall | 24sp / 700 | 页面重要数字 |
| titleLarge | 22sp / 700 | 刷题题干 |
| titleMedium | 18sp / 700 | 页面区块标题 |
| bodyLarge | 16sp / 400 | 正文和解析 |
| bodyMedium | 14sp / 400 | 普通辅助信息 |
| bodySmall | 12sp / 400 | 次要元数据 |
| labelLarge | 14sp / 600 | 按钮和计时器 |
| labelMedium | 12sp / 600 | 标签、题型、状态 |

中文题干和解析的默认行高建议 1.5 以上。

### 4.4 间距与尺寸

统一 4dp 基础栅格：

```text
space1 = 4
space2 = 8
space3 = 12
space4 = 16
space5 = 20
space6 = 24
space8 = 32
space10 = 40
```

交互尺寸：

- 普通列表行最小高度：56dp；
- 选项最小高度：52dp；
- 按钮最小高度：48dp；
- IconButton 可点击区域：48×48dp；
- 颜色选择器点击区域：48×48dp；
- 模拟卷答题卡格子：至少 48×48dp，视觉圆点可以小于 48dp，但外层点击区域不能小于 48dp。

### 4.5 圆角、边界和阴影

- 页面主卡片：16dp；
- 小标签：8dp；
- 输入框：12dp；
- 按钮：12dp；
- 不使用多层阴影，以边界和表面色区分层级；
- 毛玻璃 AppBar 保留，但降低背景透明度对文字的影响；
- 同一页面不超过三种圆角半径。

## 5. 通用组件规划

建议新增 `lib/ui/widgets/`：

```text
app_page_shell.dart       # 页面最大宽度、滚动、安全区
app_section_header.dart    # 标题 + 辅助信息 + 操作
app_state_view.dart        # loading/error/empty/retry 统一状态
app_icon_tile.dart         # 统一图标容器 + ListTile
app_action_card.dart       # 主行动/次行动卡片
app_progress_bar.dart      # 统一进度条
app_metric_tile.dart       # 统计数字单元
app_semantic_badge.dart    # 题型、正确、错误、状态标签
```

通用状态组件至少支持：

```dart
AppStateView.loading()
AppStateView.error(message: ..., onRetry: ...)
AppStateView.empty(icon: ..., title: ..., message: ..., action: ...)
```

这样可统一首页、题库页、刷题页、错题本、模拟卷和统计页的反馈体验。

## 6. 页面改版优先级

### P0：影响核心体验，优先实现

1. 统一刷题页题干、选项、解析和评分区层级；
2. 统一加载/错误/空状态，并为失败页面增加重试；
3. 首页重排为“今日任务优先”；
4. 修复深色模式背景图遮罩；
5. 修复底部导航隐藏后的点击穿透；
6. 处理首页顶部状态胶囊窄屏溢出；
7. 统计页四指标改为响应式网格或可换行布局。

### P1：提高一致性和可访问性

1. 统一间距、卡片、图标容器和标题样式；
2. 所有选项状态同时提供颜色、图标和文本反馈；

## 10. 最终设计原则

1. **主路径优先**：用户打开首页后，第一眼应该知道今天该做什么；
2. **题目优先**：刷题页的题干和选项永远高于装饰、章节和统计信息；
3. **状态可恢复**：错误、空数据和加载失败必须告诉用户下一步怎么做；
4. **不用颜色单独表达含义**：正确、错误、选中、禁用都要有图标或文字辅助；
5. **视觉统一而非全部相同**：普通章节、重点章节、随机刷、论述题专题需要有不同层级；
6. **尊重数据边界**：UI 可以重排和解释已有数据，但不新增未经业务定义的统计结论；
7. **计时可见性只是显示设置**：计时底层、日志和统计必须始终正常运行；
8. **所有改版都以业务回归测试为前提**：界面改动不能改变判题、提交和统计结果。
