# 考研刷题 App —— 题库包结构规划（formatVersion=2）

> 编制日期：2026-08-16（v2：按用户确认更新——真题单独文件/真题参考/answerFormat/formatVersion 3）
> 适用范围：阶段一内容生产线（思源知识库 → 题库包）与阶段二 App 导入的接口契约规划
> 输入依据：对思源 5 个学科笔记本的实测盘点（2026-08-16 扫描文档树 + blocks 统计），与《设计方案-考研刷题App.md》§2.4 题库包格式（**已定稿为 formatVersion=2**）对齐。
>
> 一句话结论：**5 个思源笔记本 → 5 个独立 bank（一科一包），章节沿用知识库/教材体系做标准化命名，mockPapers 每科配 1 卷起步，首批每 bank 50~100 题、先覆盖核心章节。**

---

## 0. 设计原则（先立规矩）

| # | 原则 | 说明 |
|---|---|---|
| P1 | 一科一 bank，包是独立交付/版本单元 | 5 个笔记本学科差异大、内容量不均（实测 0.8k~5.8k 块），合并成一个大包会放大"一章更新全体重导"与"导入体积"问题；App 已支持多题库并行导入 |
| P2 | `chapter` 是唯一真相 | App 用 `SELECT DISTINCT chapter` 建浏览目录；manifest.chapters 仅元数据 + 导入一致性告警。**章节名一旦随包发布即冻结**——App 按 chapter 字符串聚合统计，改名等于丢历史统计 |
| P3 | 章节命名：优先对齐知识库标题树，缺料章节用学科标准补位 | 知识库结构好的学科（古汉/现汉/文学史）直接对齐；知识库空壳的章节（元代/清代文学）按学科标准预留，宁可"空章节"也不"挂错题" |
| P4 | 每题可追溯 | `source.blockId` + `source.docPath` 必填，缺其一判为不合格（产出侧红线）；`tags` 每题 2~5 个且至少含 1 个章节核心知识点 tag |
| P5 | bankId 稳定、版本走 semver | bankId 永不含版本/年份（修正旧示例 `bank-gaoshu-2026` 的写法），保证 `(bank_id, version)` 增量导入语义成立 |
| P6 | 版权纪律不破 | 知识库内的"本章真题汇总 / 题库答案"文档只作**考点提示与解析依据**，出题一律改写/原创，题干不与真题原文逐字重复（对齐主设计 §5/§6 红线） |

## 1. Bank 划分与命名规范

### 1.1 划分决策：一科一 bank（推荐）

| 决策 | 结论 |
|---|---|
| 是否合并成 1~2 个总包 | **否**。5 个 bank 并行导入，理由见 P1 |
| bank 内是否再拆 | 否。每 bank 内章节 + tags 已足够切分；拆包徒增 mockPaper 跨包引用复杂度 |
| 交付节奏 | 按 bank 独立分批交付（先现汉/古汉，再文学史三包） |

### 1.2 bankId / name / version 命名规范

- **bankId**：`bank-<拼音kebab>`，仅小写字母与连字符，**稳定不变**（跨版本复用，供增量导入比对）。
  - 不建议带年份/学科编码（如 `bank-xiandai-hanyu-2026`），否则每次换代都要处理旧 id 的归档语义。
- **name**：`考研 · <学科名>`，展示用。
- **version**：semver。内容首批 `0.1.0`；任一包内题目增删改后升 patch/minor，正式对外 `1.0.0`。
- **题目 id**：`{bankId}:q_{6位零填充序号}`，如 `bank-xiandai-hanyu:q_000123`。
  - 序号分配规则：打包工具维护"id 分配表"，按 `(source.blockId, stem归一化hash)` 绑定 id——**同一素材同一题干跨版本复用同一 id**（增量的前提）；新题追加新号；删除只软归档不重排号。
- **mockPaper id**：`mp-{bank短名}-{序号}`，如 `mp-xianhanyu-01`。
- **chapter 字符串**：见 §2，发布后冻结（P2）。

### 2.6 manifest 写法约定（formatVersion=3）

- **formatVersion 升级说明**：v3 在 v2 基础上新增 `answerFormat`（简答答题格式）与 `questionFiles`（questions 多文件）支持；App 兼容 v2/v3（v2 单 questions.json 继续可导）。
- `chapters` 数组 = 上表"chapter 列"的全部取值（含预留），与题目 `chapter` 字段同源同串。
- 打包校验（质量门槛之一）：**每道题的 chapter 必须命中 manifest.chapters**，命中失败判不合格（杜绝"未分类"垃圾章；真正的杂题归 `未分类` 需人工确认）。
- 跨 bank 无共享章节命名（各科独立体系），App 侧按 bank_id 隔离展示。
- **`questionFiles`（v3）**：显式列出 `questions/` 目录下的题目文件（打包校验文件齐全）；App 缺省也扫描目录全部 `.json` 兜底合并。文件组织见 §7.3。

## 3. mockPapers 规划

### 3.1 适用性判断

| bank | 是否配模拟卷 | 理由 |
|---|---|---|
| 现代汉语 | **是** | 素材量最大（含 688KB 题库），客观题（选择/填空/判断）产出容易，适合"单元卷 + 综合卷"两层 |
| 古代汉语 | 是 | 语言类客观题占比高（含翻译题可作填空/简答），可配综合卷 |
| 古代文学史 | 是 | 客观题（单选/填空/判断）+ 名解/简答/论述，适合专业课综合模拟 |
| 现代文学史 | 是 | 同上，作家/作品题量大 |
| 当代文学史 | 是（量小先配 1 卷） | 素材量最小，先出 1 卷验证 |

> **开放问题**：mockPapers 定义在单包 manifest 内、`questionIds` 指向本包题目。若未来要"文学综合卷"（跨三科文学史抽题），需 App 侧引入包外卷定义或 formatVersion 3 扩展——本期不做，记录待定。

### 3.2 客观题占比设计建议

- **模拟卷客观题（单选/多选/判断/填空）占比 ≥ 60%**：保证"交卷即自动判分"的模考体验；主观题（简答/论述/翻译/写作）占比 ≤ 40%，判分走"看答案自评"，但**模考卷内必须每题都有 `explanation` 参考答案**，自评才成立。
- 语言类（古汉/现汉）偏客观：75%~80%；文学类偏主观：60%~67%。

> **真题参考（用户要求）**：组卷与出题均参考知识库"本章真题汇总"的考点标注（院校+年份+题型，如"陕师19年·名词解释"）——高频考点最先入池；真题原文不复制（版权红线），只借鉴考点方向，题目标注 `真题参考` tag 与 `source.docPath`（指向真题汇总文档）供追溯。

### 5.2 题型与难度分布建议（质量门槛模板）

| bank 类别 | 单选 | 多选 | 判断 | 填空 | 名解 | 简答/翻译/论述 |
|---|---|---|---|---|---|---|
| 语言类（古汉/现汉） | 40% | 8% | 12% | 20% | — | 20% |
| 文学类（三科文学史） | 30% | 8% | 12% | 20% | 15% | 15% |

- 难度：easy 40% / medium 45% / hard 15%（模考卷按 4:4:2 组卷，见 §3.4）。
- 主观题下限：**每个 bank 每章至少 2 道简答/名解**（保证"背题模式"与自评场景有料）；**主观题必带 `answerFormat` 答题格式**（名解/翻译/断句/论述模板见《题型规划.md》§4）。
- 出处可追溯红线：`source.blockId`、`source.docPath` 必填；审核阶段按 5% 抽检 blockId 可在思源定位；解析文本如引用笔记原文须标注 `source.note`；**真题改编题 `source.docPath` 指向"本章真题汇总"文档**，tag 含 `真题参考`。

### 5.3 每 bank 的生产批序

1. **批 1（核心章节）**：S2 先跑内容量最大的 2~3 章（见 §6 优先级表），出 50~100 题 → 审核 → 打 0.1.0 包。
2. **批 2（补全章节）**：补齐其余章节至每章 ≥10 题 → 0.2.0。
3. **批 3（模考 + 主观题）**：组 mockPaper、补简答/论述 → 0.3.0 / 1.0.0。
4. 后续：随笔记更新按 (blockId, stem) diff 增量重导，version 升 patch。

### 6.2 章节覆盖策略

- **覆盖顺序**：核心章节（内容量大 + 高频考点）→ 次级章节 → 预留章节。预留章节（元代/清代文学）**暂不出题**，待用户补笔记后再补包，不做"为凑章节而硬出"。
- **首批不追求全章覆盖**：0.1.0 允许存在"未出题章节"（App 自然不显示），但 **0.2.0 前每 bank 已出题章节数 ≥ 有料章节的 90%**，且已出题章节每题量 ≥ 10。
- **真题优先（用户要求）**：有"本章真题汇总"标注的章节/考点**最先出题**（批 1 覆盖）；其标注题型必须出到（如标注了名词解释→该章至少 1 道简答名解）。
- **考点覆盖硬门槛**：每章核心知识点 tags 词表覆盖率 ≥ 80%（打包报告按"已出题 tag / 词表 tag"统计）。
- **难度与题型双覆盖**：每章内题型 ≥ 3 种、难度三档齐备（判定用 §5.2 分布模板，超差打回 S2 补题）。

### 6.3 体积预估

- 纯文字题：1 题 ≈ 0.8~1.5 KB（题干+选项+解析+source）→ 1000 题 ≈ 1~1.5 MB，zip 后更小，内置 asset 无压力；media/ 目录一期不启用（纯文字题），为二期公式/图片预留目录规范。
