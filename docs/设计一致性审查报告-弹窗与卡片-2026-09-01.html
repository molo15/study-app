弹窗与卡片设计一致性审查报告

考研刷题 App · UI v2 冷磨砂设计体系核查 · 只审查不改动 · 2026-09-01

审查结论速览

维度总体判定核心问题
弹窗不一致 17 个弹窗点中 16 个使用 Flutter 默认 Material 3 实色样式（无磨砂、无白边高光、圆角默认 28），与冷磨砂设计方向脱节；仅 SnackBar 走统一主题
卡片部分统一 磨砂卡片存在 两套重复实现（GlassCard / AppCard），且仅 4 个页面启用；约 12+ 个页面仍用原生 Card（半透明白、无 BackdropFilter 模糊），与磨砂卡视觉不齐

一、当前设计方向基准（UI v2 冷磨砂）

审查以 AppThemeConfig 冷磨砂预设（frost=true，默认主题）为基准，其设计语言包括：

  • 背景：渐变端点 #E7EEF7 → #C9D7EA + 光斑（FrostBackground）
  • 卡片：毛玻璃 = BackdropFilter 模糊（blur 14–26）+ 半透明白渐变 + 白边描边 + 顶部高光 + 柔和阴影
  • 圆角：cornerRadius = 18（配置驱动；AppRadius 规范：卡 16 / 输入 12 / 小 8）
  • 强调色：冷青蓝 #4F7CD4
  • 间距：4dp 栅格（AppSpacing）
  • 导航：底部 dock 玻璃悬浮，无独立底板
⚠️ 关键缺口：buildThemeData() 中未配置 dialogTheme / bottomSheetTheme / datePickerTheme——弹窗类组件因此回落到 Flutter 默认 M3 样式，脱离上述设计语言。

2.2 浏览器取证（代码 + 渲染对照）

代码层面已逐点确认 AlertDialog/SimpleDialog/showModalBottomSheet 均未自定义 backgroundColor/shape（或仅设实色），渲染层面通过语义交互尝试弹出对话框，交互在自动化环境不稳定，故以代码结构为主证、以设置页卡片渲染为对照。

代表性对照：首页/题库页的 GlassCard/AppCard 渲染为玻璃质感（白边 + 高光 + 背景模糊）；同屏可见；而弹窗类如未能拦截取证，其 M3 默认样式由 Flutter 框架确定，与本设计体系无任何绑定。

三、卡片审查（三套基元并存）

3.1 卡片基元盘点

基元样式当前使用页面（次数）判定
GlassCard磨砂玻璃（BackdropFilter + 半透明白渐变 + 白边 + 顶部高光 + 阴影），三档强度 题库首页 ×2、背题首页 ×2 符合方向
AppCard磨砂玻璃（与 GlassCard 几乎同构，三档 depth）；代码注释声称"全 App 统一卡片" 首页 ×3、设置页 ×1 重复实现
原生 Card走 CardTheme：半透明白（cardOpacity 0.72）+ 圆角 18 + 无阴影，无 BackdropFilter 模糊 统计 ×5、设置 ×4、背题 ×3、题库 ×3、模拟考列表 ×2、历史 ×2、知识背诵 ×2、错题本、章节列表、章节概览、主题面板等 12+ 页面 不一致

结论：卡片存在三套实现，且冷磨砂模式只覆盖了首页/题库/背题首页/设置少量区域；大量业务页（统计、背题、模拟考、错题本、章节等）仍用无模糊的原生 Card，与 AppCard 注释"全 App 统一"不符，是 UI v2 改造未完成迁移的遗留。

3.2 视觉差异说明

  • 磨砂卡（GlassCard/AppCard）：背景被 模糊（22px blur）+ 白描边 + 顶部高光 + 蓝调阴影 → 立体"玻璃"质感；
  • 原生 Card：半透明白平片，背景渐变/光斑直接透出但不模糊，无白边、无高光 → 视觉偏"平、薄"；
  • 在浅色纯色背景下两者差异较小（这也是截图不易察觉的原因），但在光斑/深色/背景图场景下差异明显放大。

四、问题分级与建议（供后续参考，本轮未改动）

P1 · 高

统一弹窗主题
在 buildThemeData() 增加 dialogTheme / bottomSheetTheme / datePickerTheme，将弹窗背景/圆角/描边与冷磨砂玻璃体系对齐。改动面小（1 个文件），收益最直接。

P1 · 高

合并磨砂基元
GlassCard 与 AppCard 功能重复（同为三档玻璃强度），建议保留一个统一基元（如以 AppCard 为唯一出口，GlassCard 转为别名或删除），消除双实现维护成本。

P2 · 中

迁移原生 Card → 磨砂基元
将统计/背题/模拟考/错题本/章节等 12+ 页面原生 Card 替换为统一磨砂基元，使全 App 卡片质感一致；迁移后用真实浏览器对照验证。

P2 · 中

校验非冷磨砂预设
现有 4 套旧主题（墨绿/纸米/经典蓝/夜间 frost=false）走回退实色路径，弹窗/卡片统一后需回归这 4 套主题下仍可读、不破版。

建议落地顺序

① 补 dialogTheme/bottomSheetTheme（弹窗玻璃化）→ ② 合并 GlassCard/AppCard → ③ 原生 Card 全量迁移 → ④ 4 套旧主题回归 + 多尺寸/深色截图验收。

本报告为审查性产物，未对代码做任何改动；如需按上述顺序实施，可在确认后进行。
审查方法：静态代码盘点（lib/ui 全量 showDialog/showModalBottomSheet/AlertDialog/SimpleDialog/Card/GlassCard/AppCard 扫描）+ 主题配置核查（buildThemeData 是否声明弹窗主题）+ 浏览器渲染对照取证。
