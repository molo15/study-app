# 多端存档同步实施方案 v1.1

> 新方向：三端交付（Web / Android APK / Windows EXE）+ 文件存档为核心的多端数据流转。
> 2026-08-31 定稿。技术路线：**继续 Flutter**（一套代码三端编译，不重写）。

---

## 一、目标与设备矩阵

**核心思想**：存档文件（Archive File）是用户数据的唯一核心。用户状态围绕它转，任意端可导出、任意端可导入，端间通过文件流转（微信 / 网盘 / USB / 浏览器下载上传），无需服务器、零成本。

**重要边界**：存档承载的是**用户状态**（做题记录/复习调度/设置等），**不是题库内容**。题库包是随 App 内置的内容资产，由 App 内置包 + `seed_loader` 统一管理，**不进存档、不被存档覆盖**（原因见 §2.5）。

| 设备 | 系统 | 交付形态 | 存档流转方式 |
|---|---|---|---|
| 电脑 | Windows | EXE + Web | 文件系统直接读写 |
| iQOO 手机 | Android | APK | 下载目录 / 分享 |
| iQOO 平板 | Android | APK | 下载目录 / 分享 |
| iPad mini 5 | iOS | **Web / PWA**（Windows 无法构建 iOS 原生包） | 浏览器下载存档 + 上传导入 |

> ⚠️ **现实约束**：当前开发机为 Windows，`flutter build ios` 需要 macOS，故 iPad 端只能用 Web（PWA 加主屏）。这也与"以 web 为主"的方向一致。

## 二、存档系统设计（核心）

### 2.1 存档格式（formatVersion=3，替代现有 v2 JSON 备份）

```
quiz_archive_20260831_153000.zip   ← 压缩存档（zip，用已有 archive 依赖）
└── archive.json
```

`archive.json` 结构：

```jsonc
{
  "formatVersion": 3,
  "exportedAt": "2026-08-31T15:30:00+08:00",
  "appVersion": "1.2.0",
  "kind": "manual" | "auto",          // 手动导出（跨端流转）/ 自动存档（本地保险）
  "bankVersions": { "xdhy": "0.14.0", "gdhy": "0.14.0" },  // 题库版本清单（跨端校验）
  "userState": {
    "answerLogs": [...],          // 做题记录（统计由此重建）
    "cardScheduling": [...],      // FSRS 调度
    "memorizeProgress": [...],    // 背题进度（v3 新增，v2 缺失）
    "wrongBookExclusions": [...],
    "mockPapers": [...],
    "mockSessions": [...],
    "reviewFlags": [...],         // 审题标记（v3 新增，v2 缺失）
    "settings": [...]
  }
}
```

**v3 相对 v2 的变化**：
1. **补齐用户状态**：新增 `reviewFlags`（审题标记）、`memorizeProgress`（背题进度）
2. **剔除 questions**：v2 导出含净化题目，v3 **不再含题目**（题库以 App 内置包为准，避免与题库包管理冲突，见 §2.5）
3. **题库版本清单**：`bankVersions` 供跨端校验（各端题库包须同版本，否则警告）
4. **压缩 + 类型标记**：zip 打包；`kind` 区分手动/自动

### 2.2 两种存档 & 覆盖压缩机制

**手动导出（跨端流转）**：用户主动触发，导出到系统下载目录（Android 走原生 MediaStore），含全部用户状态。保留为跨端媒介。

**自动存档（本地保险）**：定时（每 30 分钟）+ App 生命周期暂停时，写入应用文档目录 `archives/`，文件名带时间戳；**只写用户状态**（本地已有题库包，无需自包含）→ 序列化轻量、不卡 UI。保留最近 **5 份**，超出删最旧（覆盖压缩）。

> ⚠️ **"退出时"不可靠**：移动端后台可能被系统杀掉，`detached` 不一定触发。生命周期监听为**尽力而为**，真正的保险是定时 + 手动导出。

**开关**：设置页「自动存档」开关（默认开）；手动导出按钮始终可用。

### 2.3 数据范围（同步的"具体类型和范围"）

**同步（进存档，全部用户状态）**：做题记录、FSRS 调度、背题进度、错题本排除、模拟卷与考试记录、审题标记、设置。

**不同步（不进存档）**：题库包本体（随 App 内置）、模拟考进行中的临时会话、日志、运行时缓存。

### 2.4 存储后端抽象（web 适配关键）

存档系统需抽象 `ArchiveStore` 接口，各端实现不同后端：

| 端 | 自动存档位置 | 手动导出位置 | 说明 |
|---|---|---|---|
| Android / Windows | 应用文档目录 `archives/` | 下载目录（Android MediaStore / 桌面文件系统） | 现有 `exportToDownloads` 扩展 |
| Web | **OPFS / IndexedDB**（浏览器持久化存储） | 浏览器下载（`<a download>`）+ 上传导入 | Web 无文件系统、无后台任务，自动存档靠定时 + OPFS |

### 2.5 为什么不把题库放进存档（架构论证）

| 理由 | 证据 |
|---|---|
| 与题库包管理冲突 | `seed_loader` 幂等导入会按稳定 id **upsert**，且特定情况**整库清空再导入**；存档若含题目，与题库包导入/更新/归档逻辑互相覆盖 |
| 与题库包更新冲突 | 旧题库版本的存档导入会把题库"回退"，与 App 内置包版本错位 |
| 体积与性能 | 5 科几千题序列化 + zip 压缩，30 分钟一次的自动存档会卡 UI |
| 语义 | 用户要的是"当前所有**状态**"，题库是内容资产不是状态 |

**跨端题库一致性**：各端安装同一题库包版本（内置包随版本发布保持一致）。导入时校验 `bankVersions` 与本地 `importedVersion`，不一致则**警告**（"题库版本不同，做题记录可能无法匹配"），由用户确认后继续或取消。

### 2.6 导入安全

- 入口改为读文件字节（`Uint8List`）：**自动识别 zip 魔数**（`PK\x03\x04`）解压，否则按 v2 纯 JSON 文本处理（**v2 兼容**）
- 校验：`formatVersion` / `kind` / 核心字段；v2 备份含 `questions` → 导入时**忽略题目字段，只恢复用户状态**（题库以本地为准，行为统一）
- 题库版本校验（§2.5）
- 全量恢复（事务内：先自动备份当前状态到 `archives/`，再清空写入）；非法文件整体回滚，杜绝误传损坏文件静默清空数据（沿用现有 `restoreJson` 回滚保护，签名从 String 扩展为 Uint8List）

### 2.7 导入入口 UI 适配

现有 `_importBackup` 用 `FilePicker` 限定 `.json` → 改为允许 `.json` / `.zip`，自动识别。

## 三、多端构建方案

### 3.1 Web 版（最大技术风险点，先 spike）

- **数据库**：`sqflite` 不支持 Web → 引入 `sqflite_common_ffi_web`（SQLite wasm，复用现有 sqflite API，改动最小）
- **持久化**：OPFS / IndexedDB。⚠️ OPFS 需 iOS 15.2+，**iPad mini 5 若系统版本过低则持久化失效**，需真机确认；失效则退化为"存档文件驱动"（每次导入存档在内存/IndexedDB 运行）
- **适配**：响应式布局（宽屏电脑 / 平板 / 手机竖屏），触摸 + 鼠标交互，滚动流畅性（重点 iPad mini 5 Safari）
- **PWA**：manifest + 加主屏，离线缓存，图标
- **文件流转**：下载存档（浏览器下载）/ 上传导入（文件选择器）

### 3.2 Android APK（已有构建管线，沿用）
- `flutter build apk --release`，iQOO 手机/平板直接安装
- 存档导出已走原生 MediaStore，导入用文件选择器（扩展名改 .zip/.json）

### 3.3 Windows EXE
- `flutter build windows`（需 VS Build Tools C++ 工作负载，**实施前确认开发机环境**）
- 存档直接读写文件系统

## 五、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| Web 数据库（wasm）与 OPFS 持久化可行性（含 iPad 系统版本） | 高 | Phase 2.1 spike；OPFS 不可用则退化为存档文件驱动 |
| Windows EXE 构建依赖 VS 工具链 | 中 | 实施前确认开发机环境，缺失则安装 VS Build Tools |
| iOS 无法原生构建 | 中 | iPad 走 Web/PWA（设备矩阵已明确） |
| 存档版本兼容（v2→v3 互导） | 中 | v3 导出 + v2 导入兼容（忽略 questions）；跨版本字段缺失给默认值 |
| 跨端题库包版本不一致 | 中 | 存档带 `bankVersions`，导入校验并警告 |
| 自动存档卡 UI（含题库序列化） | 低 | 自动存档只写用户状态（§2.2） |
