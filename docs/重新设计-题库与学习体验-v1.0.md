# 题库与学习体验重新设计方案（v2.0）

> 版本：v1.0（草案）
> 日期：2026-08-27
> 定位：针对正式版 v1.0.0（内置题库 0.9.1，5 科 5037 题）暴露的题库质量与学习体验问题，做一次系统性重新设计。
> 适用范围：内容生产线（tools/seed-builder）→ 题库包格式 → 判分层 → App 功能。
> 配套：《设计方案-考研刷题App.md》《题型规划.md》《题库包结构规划.md》《PROJECT_PROGRESS_2026-08-24.md》

## 0. 一句话结论

以**知识点实体**为新的中心数据（连接 题目↔概览↔统计），对内容生产线加**强制质量门禁**（选项洗牌/去重/解析/等价答案/覆盖率），对判分层修**等价答案语义并支持部分得分**，对 App 补**章节知识概览 + 背题模式 + 学习目标**。题库包升级到 **formatVersion=4**。

> 数据来源：`tools/seed-builder/out/v09*/bank-*.v09.json` 全量扫描（古汉 978 / 现汉 1182 / 古文史 707 / 现文史 1430 / 当文史 768，合计 5065 题）。

### 1.1 六个使用问题

| # | 问题 | 数据证据 | 主责层 |
|---|---|---|---|
| 1 | **题目重复** | 古汉语 11 组完全重复题干（23 题），如"假借者，本无其字______"出现 2 次、"名词解释：词牌"2 次 | 生成管线 |

| 4 | **基础题不够基础** | 抽样：干扰项带括号注释一眼穿帮（"用典（引用）"）、题干语法错误（"出自？的"）、简答被"选择判断化"（现代文学史"属于哪一种戏剧运动"实为选择题） | 生成管线 |

| 6 | **无背题模式** | App 仅做题（刷题/复习/模考），无浏览式背题 | App |

### 1.2 解析问题（四类，用户补充）

| 类型 | 表现 | 数据证据 |
|---|---|---|
| ① 完全缺失 | 无解析字段 | 现代汉语 75 题（6.3%）缺失，集中在填空 38、简答 36 |
| ② 占位/敷衍 | 有字段无内容 | 古汉翻译题解析="参考答案见文末翻译。"；现汉判断="原文对辞格套用的定义。"；个别解析为单个"。" |
| ③ 出处冒充解析 | 只写真题来源，不解释对错 | 古代文学史 91 条短解析全为"首师大真题""南开真题"等；当代文学史="（中山大学2011年研）" |

## 2. 中心设计：知识点实体（新地基）

> 现状题目只挂 `chapter + tags`，知识点是散的——知识概览、基础题定位、薄弱点推荐、覆盖率验证全部无根可依。**知识点实体是串起所有需求的中心线。**

### 2.1 数据结构（题库包 v4 新增 `knowledge` 清单）

```json
{
  "id": "k_gudai_hanyu_0301",
  "name": "六书",
  "parent": "k_gudai_hanyu_0300",
  "chapter": "汉字的结构（六书）",
  "hot": true,
  "summary": "六书是古人分析汉字结构归纳出的六种造字用字方法：象形、指事、会意、形声、转注、假借。",
  "aliases": ["六书说", "六书理论"],
  "relatedTags": ["六书", "象形", "指事", "会意", "形声"],
  "examRef": "陕师 20 年·名词解释"
}
```

- `parent` 构成**知识点树**（对应章节知识概览的思维导图形态）；
- `hot=true` 表示高频考点（对应素材 h 标题块★数，由骨架阶段标注）；
- `examRef` 为真题考点参考（仅标记，不复制真题原文，延续 P6 版权纪律）。

### 2.2 题目关联

- `Question` 新增 `knowledgeId`（可 1~2 个），由出题阶段从素材对应知识点推断、打包校验必填。
- 由此形成 `知识点 → 题目` 一对多映射，支撑：章节概览"该点关联 N 题"、薄弱点推荐直达题目。

### 2.3 App 侧

- 新增表 `knowledge(id, name, parent, chapter, hot, summary, aliases)`；`questions` 加 `knowledge_id`。
- 统计新增 `knowledge_stats`（按知识点聚合答对率）——支撑薄弱点推荐与难度校准。

## 3. 四层改造方案

### 第 1 层：题库包格式升级（formatVersion=4）

| 项 | 改动 | 解决 |
|---|---|---|
| `knowledge` 清单 | manifest 新增知识点树（见 §2.1） | 问题5、4、A1 |
| `overview` | 每章知识概览：`summary` + 知识点树 + 每点关联题数 | 问题5 |
| `answerVariants` 严格语义 | **一个组 = 一个空/要点的全部等价表述（组内任一命中即该空/要点对）；组数 = 空/要点数**。打包校验器自动拆分/打回组内含顿号的复合答案 | 问题2 |
| 复合答案 `separable: true` | 组内可声明"整句、散句"这类答案允许**子项分别命中** | 问题2 |
| `questionFiles` | 明确"练习/真题改编"分文件（沿用题型规划 §6），manifest 统计真题改编题数 | A3 |
| `answer` 编码 | 选择题 answer 存**正确选项文本**，洗牌后由打包重算位置 | 问题3 |

### 第 2 层：内容生产线改造

#### 2.1 选项洗牌后处理（P0，最关键）

- `pack_bank.py` 打包阶段**强制洗牌**每道选择题选项顺序，按洗牌后位置重写 `answer`（基于正确项文本匹配，不依赖原 key）。
- 目标：答案位置均匀随机（A/B/C/D 各 ≈25%）；历史已发布题在下次打包时自动校正。

#### 2.2 出题规则重写（P1）

- **基础题 = 知识点直问直答模板**：如"六书指哪六种？""普通话声母有 __ 个"。禁止引文理解题/综合分析题进入基础轨（purpose=basic）。
- **同域干扰项硬性要求**：干扰项与正确项同知识域、等长、不带注释/括号标记；禁止"用典（引用）"式穿帮。
- **按知识点清单出题**：以 §2 知识点树为纲逐点覆盖，杜绝"无重点感"。
- **题型定位纠偏**：简答/名解不得"选择判断化"。
- **解析内容质量要求**（见 §4 G5）：解析必须实质解释"为何对/为何错"，回扣题干与选项依据。

#### 2.3 强去重（P0）

- 合并阶段用**考点指纹**去重：`(chapter, knowledgeId, 题干归一化hash, 答案hash)` 四元组；近义题干按编辑距离阈值拦截。
- 重复题仅保留 1 条（真题/解析更优者），删除在 report 留痕。

#### 2.4 覆盖率报告（P0/P1）

- `pack_bank.py` 每次打包生成 `coverage_report.md/json`：章节覆盖率、知识点覆盖率（已出题知识点/词表）、题型覆盖、真题考点命中率、重复删除记录。
- 未达门槛（章≥10 题、知识点覆盖≥80%）**打回补题**，报告进 `out/<bank>/reports/`。

### 第 3 层：判分层与作答体验

| 项 | 改动 | 解决 |
|---|---|---|
| 等价答案语义 | 修 `_blankMatch` 数据层 bug（组内 `any` 即对，组间 `every`）；复合答案支持 `separable` 子项 | 问题2 |
| **部分得分** | 填空/简答按"空/要点"计：答对 M/N 返回 `Grade.partial`；成绩单按要点给分；答题卡显示"半对"态 | 问题2 |
| 填空多框 UI | 按空数渲染多个输入框，逐空判定（替代单框猜分隔） | C1 |
| 多选反馈细分 | `partial_missing`（漏选）/ `partial_extra`（多选），解析页提示 | C2（可选） |
| 简答自评 | 主观题作答后展示参考答案+要点清单，用户三选（会/部分/不会），结果进 FSRS | B4 |

### 第 4 层：App 功能

| 功能 | 实现 | 解决 |
|---|---|---|
| **章节知识概览页** | 进章节前展示：知识点树（可展开大纲/导图形态）+ 热度标记 + 每点关联题数；点击直达该知识点刷题 | 问题5 |
| **背题模式** | 新增"背题"入口：卡片流（题干→点显示答案/解析→标"会/不会"→下一张），不做答不判分不进错题本；**"不会"不进 FSRS 复习队列，按"不背单词式"会话内循环推送，直到背会**（详见 §3.5） | 问题6 |
| 知识点速览 | 概览页一键"全部展开/折叠"，考前纯浏览 | B5 |
| 学习目标 | 设置页：每日新题量、每日复习量、考试日期→首页任务卡+倒计时；**考试倒计时与计划倒排为可选功能，用户充分自定义**（详见 §3.5） | B1 |
| 薄弱点推荐 | 统计页"薄弱点 Top N"（知识点答对率最低），点击直达 | B3 |
| 难度校准 | 按知识点答对率回写 `difficulty_revised`（答对>85% 降档、<50% 升档） | A4 |
| FSRS 参数化 | 设置页暴露每日新题上限、desired_retention 滑块 | B2 |

### 3.5 背题模式与学习目标（细化设计）

#### 背题模式 —— "不背单词式"推送（用户决策）

- **定位**：纯浏览记忆，不判分、不写 `answer_logs`、不进错题本、不进 FSRS 复习队列。
- **交互流**：卡片流（题干 → 点显示答案/解析 → 标「会 / 不会」→ 下一张）。
- **推送机制**（不背单词式）：
  1. 当前会话内维护 `pending` 队列，标「不会」的题进入；
  2. 继续背后面的题，`pending` 中的题在**后续位置再次出现**（默认每过 N 张插入一次，N 可在设置调整）；
  3. 直到标「会」才移出 `pending`；
  4. 会话结束时仍未背会的题：默认**仅在会话内保留**（下次进入背题可选择"继续上次未背会"续背，可选开关）。
- **与 FSRS 完全隔离**：背题结果不干扰正常复习调度；同一题仍可正常刷题/复习。

#### 学习目标 —— 倒计时与计划倒排（可选，用户决策）

- **必做简单版**：每日新题量、每日复习量、考试日期 → 首页任务卡 + 倒计时。
- **可选增强**：考试倒计时 + 计划倒排（按剩余天数反推每日任务）。
- **自由度原则**：倒排结果仅为**建议**，用户可逐项覆盖（自定义每日量、跳过某天、暂停倒排）；不强制跟随计划；倒排可随时开/关。

## 4. 质量门禁清单（打包校验表，全部"打回"规则）

> 落地为 `tools/seed-builder/src/validate_bank.py`，在打包前强制运行，任一不通过则打包失败。

| # | 校验项 | 规则 | 针对 |
|---|---|---|---|
| G1 | 选项洗牌 | 选择题选项已洗牌，答案位置分布均匀（打包后抽检） | 问题3 |
| G2 | 去重 | 考点指纹无重复；重复组已处置 | 问题1 |

## 5. 数据兼容与迁移

- **formatVersion 4**：App 兼容 v2/v3/v4（`supportedFormatVersion` 升为 4）；旧包无 `knowledgeId`/`overview` 时降级为"按章节浏览"，不崩溃。
- **章节冻结**：沿用 P2 原则；如需改章节名，用**别名映射表**（old→new）迁移历史统计，不直接改 `chapter` 字符串。
- **用户修改保护**：`user_edited` 逻辑保留；知识点/概览更新不覆盖用户已编辑题。
